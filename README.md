# 云创运营管理平台

财资客户服务的运营原型。数据在浏览器内存里，没有后端。刷新后回到初始演示数据。

## 运行

```bash
npm install
npm run dev
```

浏览器打开终端里打印的本地地址。生产构建：

```bash
npm run build
npm run preview
```

不装依赖、不起服务时，用浏览器直接打开 `docs/云创运营管理平台原型.html`。样式、脚本和演示数据都在这一个文件里。

## 角色切换

右上角可以换成四种身份，工作台和按钮权限会跟着变。

| 角色 | 演示账号 | 能做什么 |
| --- | --- | --- |
| 一线实施顾问 | 李敏（深圳） | 管户、执行下发、提交直联/远程实施、发起实施主单、AI 问答后转售后工单、写服务日志 |
| 分行组长 | 周衡（深圳） | 看分行全量，也能切到某个顾问的个人工作台；复核实施定级；批量移交管护；下发 CBS 营销工单 |
| 集中运营 | 陈可（总行） | 待分配池批量派单、在办批量转派、下发任务、推进实施子工单、验收 |
| 部门总 | 赵宁（总行） | 看运营部整体，跟进和催办，打开超时晾晒 |

分行账号只看本分行的客户、工单和日志。总行看全量。个人工作台按管护人再滤一层，那是视图，不是另一套数据权限。

## 和两份需求文档的关系

原型按仓库外、现已读过的两份文档实现「客户建档」和「经营服务」：

- `客户建档详细需求设计.docx`
- `CBS运营工单规划V2.0（26年8月）.docx`

这两块不再标「待详设稿确认」。

客户档案是一线真实交付客户的主数据，不是应管全量租户。建档字段按文档：档案号、企业名称、租户号、统一社会信用代码、归属分行、认证状态（已开通 / 待开通）、管护人、实施定级、行业、项目信息。定级用 8 个标签自动判定，手工改级要组长复核。信用代码命中 T01 营销工单 KYC 时强制关联，并打「转化客户」。应管同步只做到「待确认」队列。

工单按总表实现 T01–T15 和 PE01。正文有的地方写 15 类通路，主单是另列的，总表一共 16 行。手工下发七类是 T01、T02、T07、T08、T12、T14、T15。T09 必须先经过 AI 问答，至少一轮，未解决要选原因。T04、T11 不能单独创建。实施主单按要客 / 重点 / 潜力匹配子工单，进度用已完成子单数除以子单总数。服务日志记工时，关单和提交反馈时要填报并和日志对照。

## 已经能点通的流程

- 四种工作台，组长可以切到个人工作台
- 建档、信用代码查重、营销工单强制关联、定级判定和组长复核
- 组长按原管护人批量移交
- 应管租户的待关联 / 待认领
- 下发工单的接收、进度、提交、验收退回、催办、跟进、晾晒
- 按分行、指定人或要客客群批量下发
- 实施主单生成子单，子单开始 / 完成 / 挂起，服务日志挂到环节上
- AI 问答后转 T09，自处理、转二线、转研发、转需求、一线确认
- 服务日志日历、直联参数和业务参数只读、驾驶舱、知识库、角色开关、字典新增

## 仍然是演示，不是正式系统

- 没有登录和后端，刷新即重置
- AI 回答是按关键词拼的，不是模型
- AI 测试里的「运行」只改本页状态
- Excel 批量下发没有做文件解析；下发页用范围选择一次生成多张工单
- 待接收黄灯按 8 小时、处理超时按 24 小时。文档写的是「x 小时」。验收 48 小时是文档写明的
- 实施链路的标准天数、标准工时是模板里的演示配置，文档没有给具体数字
- 子工单示例里出现过 T16，总表和矩阵图对应的是 T11「新客试运行维护」，原型用 T11
- 有一处正文把要客拜访写成 T15。总表 T12 是要客拜访，T15 是业务价值线索，原型按总表
- 阶段矩阵里的权限申请、信息变更、满意度、促活没有独立编号，没有另造类型
- 调研问卷的逐项栏目在文档里指向外部模板，档案里用必传附件加可增删摘录
- 直联参数、业务参数是应管只读样例

重保客户清单取实施定级为「要客级」的档案。文档没有单独的「重保」主数据字段，工单上的客户级别另有「重保客户 / 体系要客」等枚举。

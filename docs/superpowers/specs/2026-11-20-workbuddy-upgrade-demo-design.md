# WorkBuddy 频道升级项目高保真 Demo 设计

## 目标

基于 Ardot 文件 `726782210896974` 节点 `7116:438`（频道合并项目新手引导 11.11），制作一个可在电脑浏览器中评审的移动端高保真交互 Demo。

Demo 同时提供：

- 原稿版：尽可能忠实还原设计稿的视觉、文案和流程。
- 优化版：不改变业务目标，优化信息层级、选择反馈、等待反馈和完成反馈。

## 展示形态

- 桌面浏览器居中展示手机外框。
- 产品视口固定为 `390 × 844`，外层页面允许自适应缩放。
- 手机外提供仅供评审使用的工具栏：版本切换、步骤指示、上一步、重新演示。
- Demo 使用本地模拟数据，不连接真实后端。

## 核心流程

Demo 覆盖一个完整升级闭环：

1. 功能引导：从 WorkBuddy 首页发现“频道升级为项目”能力。
2. 选择频道：从频道列表中选择需要升级的频道。
3. 确认升级：查看频道与新项目的对应关系，可修改项目名称。
4. 升级进行中：显示整体进度和当前处理项，支持后台运行提示。
5. 升级完成：显示成功结果；模拟部分失败时提供重试入口。
6. 项目首页：展示消息、成员、资料和任务已归入项目，并提示升级完成。

## 原稿版

- 保留原稿的浅色界面、底部导航、黑色主按钮、白色弹层和绿色强调色。
- 保留原稿的信息密度、卡片结构和核心文案。
- 页面切换和弹层方式遵循原稿呈现。

## 优化版

- 引导页明确说明“频道升级后会成为项目，并保留原内容”。
- 选择页强化选中状态、已选数量和下一步按钮状态。
- 确认页明确列出将迁移的消息、成员、资料和任务。
- 进行中页面显示阶段进度，而不是只有模糊等待。
- 完成页明确成功数量、失败数量和可执行的下一步。
- 在原稿版与优化版之间切换时保留当前流程步骤，便于对比评审。

## 交互规则

- 未选择频道时，“下一步”按钮禁用。
- 点击频道行可选中或取消，至少选择一个频道才能继续。
- 项目名称允许编辑；空名称不可提交。
- 升级进度使用确定性的模拟计时器推进，在 3–5 秒内结束。
- 处理中离开并返回，仍显示当前进度。
- 完成后由用户主动进入项目首页，不自动强制跳转。
- “重新演示”清空选择、进度和结果，回到引导页。

## 组件边界

- `DemoShell`：桌面背景、评审工具栏和手机外框。
- `demoMachine`：流程步骤、版本、选择项、进度与重置逻辑。
- `OnboardingScreen`：功能引导。
- `ChannelSelectionScreen`：频道列表与多选。
- `UpgradeConfirmationScreen`：升级映射和名称编辑。
- `UpgradeProgressScreen`：进度和处理项。
- `UpgradeResultScreen`：成功/部分失败结果。
- `ProjectHomeScreen`：升级后的项目首页。
- `OriginalView` / `OptimizedView`：共享数据，不共享布局细节。

## 视觉规范

- 字体优先使用系统中文字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", sans-serif`。
- 手机内容以 390 × 844 为基准，顶部状态栏和底部 Home Indicator 均需还原。
- 颜色以原稿读取值为准；实现阶段统一沉淀为 CSS 变量。
- 动效保持克制：页面横向淡入、底部弹层上移、按钮按压和进度旋转。
- 禁止使用与原稿无关的渐变、阴影堆叠和装饰性动画。

## 异常与恢复

- 未选择频道：禁用继续按钮。
- 项目名称为空：输入框显示错误，停留在确认页。
- 部分升级失败：结果页同时显示成功和失败条目，可重试失败项。
- 刷新页面：允许从头开始；不要求跨刷新持久化。

## 验收标准

- 原稿版和优化版均能完整走通 6 个步骤。
- 两个版本切换时保持相同步骤和业务数据。
- 390 × 844 视口内没有横向溢出、文字遮挡或不可点击区域。
- 上一步、下一步、返回、重置、重试和进入项目均可用。
- 流程状态逻辑有自动化测试。
- `npm test`、`npm run build` 和 `npm run lint` 均通过。

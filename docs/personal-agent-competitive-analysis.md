# 个人 Agent 竞品分析（产品 × 体验）

> 面向交互设计师的 Personal Agent 横评  
> 样本：Grok Bot、Muse、OpenAI dots、Manus Cue、腾讯 WorkBuddy、**Today AI**  
> 信息截止：约 2026 年 9–10 月公开资料

---

## 1. 分析范围与选型

**Personal Agent** 在此定义为：属于个人的、可持续工作的 AI agent——具备记忆、连接个人应用、拥有（云端或本机）执行环境，且可不依赖每次用户开口而主动推进任务。

| # | 产品 | 厂商 | 选型理由 |
|---|------|------|----------|
| 1 | **Grok Bot** | SpaceXAI（原 xAI） | 指定竞品；「持久队友 + 云电脑」范式代表 |
| 2 | **Muse** | Meta | 指定竞品；消费级、大众化 personal agent |
| 3 | **dots** | OpenAI | ChatGPT 生态入口最大；工作流型 always-on agent |
| 4 | **Cue** | Manus | 独立身份（邮箱/电话/钱包）差异化最强 |
| 5 | **WorkBuddy** | 腾讯 | 国内代表；本机执行 + 办公 IM 遥控器 |
| 6 | **Today AI** | Today（齐俊元 / 原 Teambition） | 指定补充；「鲜活记忆 + 全天连续性」；国内版接飞书/钉钉/微信 |

未纳入但可对照：Claude Cowork、Gemini Spark、阿里千问办公 / QoderWake、扣子 Coze。

## 3. 产品层对比

### 3.1 运行环境与能力边界

| 维度 | Grok Bot | Muse | dots | Cue | WorkBuddy | Today AI |
|------|----------|------|------|-----|-----------|----------|
| 默认执行环境 | 账号共用一台云 Linux | 每人一台 Secure VM | 自有云电脑；可授权连本机 | 每 agent 一台电脑 + 身份资产 | 默认本机；手机/企业可云端 | 跨端原生 + 常在线云电脑 |
| 浏览器 / 桌面操作 | 强 | 强（Secure VM + 浏览器） | 强 | 强 | 本机文件与工具为主 | 有（云电脑执行多步任务） |
| App 连接 | MCP / 插件 / Skills | Connectors（邮箱、日历、Meta 系等） | 4000+ plugins 生态 | Trip.com、Gmail、健康类等 | 微信/企微等 IM + 本地技能 | 日历/邮件/笔记/健康；国内版飞书、钉钉、腾讯文档、微信 |
| 主动触发 | Routines（日程/事件） | 目标驱动、后台推进 | 常在线、可主动研究 | Routines + 外联身份 | 定时自动化 | **默认主动**：早晚简报 + 情境变化介入 |
| 支付 / 下单 | 偏工作流，需审批 | 支持（Link by Stripe 一次性卡） | 部分支持 | 自有钱包 + 预算 | 弱（偏办公交付） | 弱；偏日程/邮件/跟进，外发需确认 |
| 多 Agent | Bot 群聊互派 | 单主人、单 Muse | 当前主推 primary dot | 多 agent 群聊协作 | 多专家 / 多 Agent 并行 | **单线程个人助理**（不强调多 agent 团队） |
| 记忆模型 | Bot 上下文累积 | 目标与偏好学习 | 跨通道学习反馈 | 按 agent 责任沉淀 | 三层记忆 | **Living Memory**：人/项目/偏好/承诺，可检视可编辑 |

**产品洞察：**

1. **「给 agent 一台电脑」已成为品类标配**——没有浏览器与文件系统，就只能停在有 API 的集成边界内。
2. **海内外分叉清晰**：海外产品偏「单主人私有云电脑」；国内 WorkBuddy 从「本机文件 + 企微群派活」长出来；**Today 国内版走第三条路——把飞书/钉钉/微信接进「全天连续性」**。
3. **能力重心不同**：Muse/Cue 更偏生活消费与外联；dots/Grok 更偏知识工作与工作流；WorkBuddy 更偏可验收办公交付物；**Today 更偏「一天是否立得住」：日程、邮件、跟进、健康信号**。
4. **Today 的品类赌注是 Continuity（连续性）而非 Cleverness（聪明）**：把可检视记忆做成产品核心，而不是把多 Bot / 强执行做成第一叙事。

### 3.2 入口与平台策略

| 产品 | 主入口 | 策略含义 |
|------|--------|----------|
| Grok Bot | 桌面、iOS/Android、特斯拉车机；与 Cursor 打通 | 高价值订阅用户 + 开发者/生产力圈 |
| Muse | 独立 App、muse.ai、WhatsApp | 借 Meta 社交入口做「人人会用」 |
| dots | ChatGPT、Slack、Teams（短信 waitlist） | 寄生最大对话与协作入口，降低换产品成本 |
| Cue | 独立 App（Web/桌面/手机） | 品类独立心智：不是聊天室附属功能 |
| WorkBuddy | 桌面工作台 + 多 IM 遥控器 | 中文办公场景渗透；IM 是遥控器而非本体 |
| Today AI | Mac / iPhone / Android / Web；国内可嵌微信对话 | 「一个线程跟你过完整天」；微信好友化降低打开成本 |

**体验设计含义：**入口决定用户的**心理模型**。嵌在 ChatGPT/WhatsApp/微信里的 agent，用户更容易当成「更会干活的聊天」；独立 App（Cue、Muse、WorkBuddy）更容易建立「我有一个数字同事」的对象感。Today 同时做两端：自有跨端 App + 微信/IM 触达，主心智仍是「一个持续认识你的人」。

|------|----------|------|
| Grok Bot | SuperGrok / Cursor 订阅档 | 付费墙较高 |
| Muse | 免费档 + $20 / $100 | 消费级下探最深 |

## 4. 体验层对比（交互设计重点）

### 4.1 核心对象模型（IA）

Personal Agent 的体验分水岭，往往不在模型能力，而在**用户脑子里要记住几个对象**。

| 产品 | 主对象 | 次对象 | 心智负担 |
|------|--------|--------|----------|
| Grok Bot | **Bot**（有名字、头衔、头像） | Skill、Routine、群聊、云电脑 | 中：对象清晰，但需理解「队友系统」 |
| Muse | **Muse**（单一个人代理） | Goal、Connector、审批 | 低：一人一 Muse，最接近「助理」 |
| dots | **Dot**（可个性化 blob） | Activity、Custom Rules、插件 | 低–中：先一个 primary dot |
| Cue | **Agent Identity**（邮箱/电话/钱包/电脑） | Group chat、Routine、预算 | 中–高：身份资产多，概念新 |
| WorkBuddy | **任务 / 专家 / 技能** | Plan/Craft/Ask 模式、结果区 | 中：功能面宽，新手易懵 |
| Today AI | **Living Memory + Day**（鲜活记忆与「今天」） | Connector、早晚简报、Community Skills | **低**：单窗口、不强制项目管理 |

**设计启示：**

- Grok Bot 把「对话」降级为 Bot 的附属，首页是 **Bot 名册（roster）** 而非 chat history——这是从 chatbot 到 agent 产品最关键的 IA 跃迁。
- Muse 故意不做多 agent，降低学习曲线，换大众可达性。
- Cue 把「身份」做成第一公民，适合需要对外联络的场景，但要教育「agent 有自己的电话/邮箱」这一新概念。
- **Today 把「记忆」做成第一公民，且可打开、可改、可删**——用户不是猜测「它为什么记得」，而是像管理通讯录一样管理 agent 的信念。这是信任设计的另一条路径（相对 Sentinel/Rules）。
- Today 的单窗口混合对话（工作与生活插话可接住）刻意对标真人聊天，反对「一个话题一个项目窗」——与 WorkBuddy / Grok 的任务/Bot 分割形成鲜明对比。

### 4.2 存在感（Presence）与可监督性

| 产品 | 状态表达 | 过程可见性 | 人机接管 |
|------|----------|------------|----------|
| Grok Bot | 头像六态：idle / thinking / working / waiting / blocked / done | 侧栏预览云电脑；标题栏活动色 | 全屏接管输入验证码/登录 |
| Muse | 消息式沟通 + 后台推进 | Secure VM；Sentinel 审批 | 审批弹窗为主 |
| dots | Activity View 看后台工作 | 可打开看电脑操作 | Custom Rules 分级 |
| Cue | 任务推进中回看；通话摘要 | 独立 workspace | 预算与审批边界 |
| WorkBuddy | 任务列表按状态筛选 | 右侧结果区、变更与预览 | Plan 模式先审计划 |
| Today AI | 早晚简报锚点；「提议 → 确认」节奏 | 记忆行可审计；任务完成后简洁汇报 | **外发动作硬确认**（邮件/改日程等） |

**体验标杆对照：**

- **Grok Bot**：异步可监督——一眼看出在干活还是在等你。
- **Today AI**：时间轴可习惯——用 morning brief / evening close-out 把 agent 嵌进「一天的开合」，主动性有仪式感但不刷屏。

这对交互设计师尤其重要：**异步 agent 最大的焦虑不是「它不够聪明」，而是「我不知道它在干嘛、要不要我」**。Grok 用状态机解决「现在」；Today 用简报解决「今天」。

### 4.3 指令与协作方式

| 产品 | 主要交互 | 特色交互 |
|------|----------|----------|
| Grok Bot | 聊天派活；@Bot；群聊 | **Teach a task**（演示录制变 Skill）；Routines |
| Muse | 像给人发消息（App/WhatsApp） | 目标 → 计划 → 自主推进；购物/健身等生活场景模板 |
| dots | ChatGPT/Slack/Teams 对话；语音 | 反馈学习偏好；并行深度任务额度 |
| Cue | 设责任 + 跟进；群聊多 agent | 扫码创建 agent；转发电话；餐厅扫码点餐等线下触点 |
| WorkBuddy | 自然语言任务；三种模式 | 专家市场、Skill 商店、结果验收面板 |
| Today AI | 单窗口持续对话；跨端同一记忆 | **早晚简报**；录音纪要接项目/人物记忆；微信里当好友聊 |

**Today 的体验亮点与风险：**

- **亮点**：无需 Prompt 工程、无需开项目窗；连上飞书/微信后「越用越不用解释我是谁」——Personal 感强。
- **风险（用户实测）**：轻重缓急判断不稳——简单问题可能被拉成长任务，关键步骤可能自信给错指令。对设计师意味着：需要**任务轻重的显式/隐式控件**（类似 WorkBuddy 的 Ask/Plan/Craft，或 Today 自身的「一句话答完 vs 后台深做」分流）。

### 4.4 信任、审批与安全感

| 产品 | 审批模型 | 安全叙事 |
|------|----------|----------|
| Grok Bot | 逐动作：允许一次 / 总是允许 / 拒绝；自然语言 Agent 规则 + 审查 agent | 隔离环境；敏感登录由人接管 |
| Muse | Sentinel 独立闸门；一次/会话/任务/限时/永久授权 | VM 隔离；agent 不见真凭证；支付用一次性卡 |
| dots | 内置规则 + Custom Rules（允许/需批/禁止） | 模型不可见保存密码；Activity 可审 |
| Cue | 用户设边界 + 消费预算 | 「有身份但权限你控」 |
| WorkBuddy | 高风险强制确认；Plan 模式审计划 | 本机目录授权；沙箱/容器执行 |
| Today AI | **Confirm-before-send**：外发/改日程等一律等人点头 | Living Memory 可审计；Connector 可选可撤销；可先纯对话再连数据 |

**体验原则提炼：**

1. **审批要可预期**：用户需知道「什么会弹、什么不弹」，否则要么骚扰要么恐惧。
2. **闸门最好在 agent 之外**（Muse Sentinel、dots Rules）——心理上更可信。
3. **预算优于无限授权**（Cue 钱包预算、Muse 一次性卡）——对支付场景尤其友好。
4. **记忆可检视是第三条信任路径**（Today）：不只控制「能做什么」，还控制「它以为你是谁」。
5. 行业共同缺口：**他人触发你的 agent 时，不可逆步骤谁批？** 国内协作型产品更需补齐这条体验链路。

### 4.5 主动性与「不打扰」平衡

| 产品 | 主动性来源 | 打扰控制线索 |
|------|------------|--------------|
| Grok Bot | Routine 日程/事件；Bot 互触发 | waiting 态 + 审批；只在判断点拉人 |
| Muse | 目标后台推进、建议 | 敏感动作审批；生活场景高频 nudge 风险需控 |
| dots | always-on、只读主动研究 | Custom Rules + Activity |
| Cue | Routine、外联来电/邮件 | 身份通道本身会引入外部打扰，需强过滤 |
| WorkBuddy | 定时任务 | 任务完成通知；偏事务交付少闲聊 |
| Today AI | 情境变化 + 早晚两个锚点 | 官方明确克制条：只推「你希望真人告诉你」的事；外发必确认 |

**设计张力：**Personal Agent 的价值来自主动性，但主动性过界 = 通知噪音 + 越权感。优秀产品会把「主动」拆成：**只读观察可以勤，写操作必须钝**。

Today 额外贡献一条可抄的产品规则：**主动性有时间锚点（早/晚）+ 内容门槛（是否影响仍来得及的决策）**，比「有事就推」更可设计。

### 4.6 情感化与品牌调性（视觉/人格）

| 产品 | 人格/视觉线索 | 对体验的影响 |
|------|---------------|--------------|
| Grok Bot | 具名队友、头像动效表达工作态 | 强化「同事感」、可监督感 |
| Muse | Meta 消费品牌、消息即交互 | 降低技术感，贴近 WhatsApp |
| dots | 可爱可个性化 blob | 亲和、降低 agent 恐惧；偏娱乐化风险需注意专业场景 |
| Cue | 「独立身份」硬核概念 | 科幻感强，教育成本高，差异化记忆点强 |
| WorkBuddy | 职场工具台、专家角色 | 效率可信，但易显复杂 |
| Today AI | 克制、像懂你的人；回答偏干练少套话 | 强 Personal 感；单窗连续性像真人聊天 |

## 5. 场景适配矩阵（设计师选型用）

| 用户目标 | 更合适 | 原因 |
|----------|--------|------|

## 6. 体验差异总结：产品轴线

用交互设计师常用的「轴线」看这六款：

```
大众易用 ←————————————→ 专业可编排
   Muse / Today      dots     Grok Bot / WorkBuddy
                     Cue（概念新但场景直观）

生活消费 ←————————————→ 职场生产力
   Muse / Cue              dots / Grok / WorkBuddy
         Today（生活+工作一天里混着走）

单助理 ←————————————————→ 多 Agent 团队
   Muse / Today / dots(初)   Grok Bot / Cue / WorkBuddy

记忆优先 ←————————————→ 执行/身份优先
   Today                   Cue（身份）/ Grok（执行队友）/ WorkBuddy（交付）

云隔离电脑 ←————————————→ 本机真实环境
   Muse                    WorkBuddy
   （dots/Grok/Cue/Today 居中，云电脑 + 可选本机/跨端）

私有单主人 ←————————————→ 可被同事派活
   Muse/dots/Grok/Cue/Today    WorkBuddy
```

## 7. 对「做个人 Agent」的设计建议（可落地）

1. **先定主对象**：是「一个 Muse/Today」还是「一名单册的 Bots」？对象模型决定导航、空状态、通知结构。
2. **Presence 必做六态级状态机**：至少区分 idle / working / waiting_on_user / blocked / done；waiting 必须可点击直达原因。
3. **电脑可见性做三级**：角标感知 → 侧栏旁观 → 全屏接管；不要一上来就甩远程桌面。
4. **把 Routine / 简报做成一级对象**：可命名、暂停、回顾结果——否则「主动性」会藏在设置里死掉。Today 的早晚锚点是可复用的习惯设计。
5. **审批按后果分级**：只读 < 发消息 < 改文件 < 花钱/删数据；支持「一次 / 会话 / 永久」与预算上限；外发默认 Confirm-before-send。
6. **记忆做得可检视**：不仅「记得」，还要让用户打开、修正、删除事实行——这是 Today 最值得抄的信任交互。
7. **做任务轻重分流**：一句话直答 vs 后台长任务必须可区分（控件或智能默认 + 可撤销），否则主动执行会反噬体验。
8. **Onboarding 教正确用法**：WorkBuddy 教「扔完整任务」；Today 教「先聊、再逐步连日历/邮件」——分阶段授予权限更像真人助理。
9. **国内产品额外设计「他人派活」审批链**：谁发起、谁可见、谁批准不可逆步骤——这是差异化机会，也是风险点。

## 8. 竞品速览卡（可直接贴评审）

### Grok Bot
- **产品**：持久 AI 队友；共用云电脑；Skills + Routines；Bot 间协作。
- **体验**：Roster > Chat；头像状态机；电脑旁观/接管；示教成 Skill。
- **适合学**：异步可监督、多 agent 团队的 IA。

### Muse
- **产品**：大众个人 agent；Secure VM；目标驱动；连接生活 App；可购物支付。
- **体验**：消息即主交互；WhatsApp 入口；Sentinel 审批；低学习曲线。
- **适合学**：消费级信任设计、降低 agent 恐惧。

### OpenAI dots
- **产品**：ChatGPT 生态 always-on agent；云电脑 + 海量插件；Activity + Rules。
- **体验**：寄生已有工作入口；blob 人格化；语音；企业 specialist 路线。
- **适合学**：平台分发、规则化权限、工作场景渗透。

### Manus Cue
- **产品**：每 agent 自有邮箱/电话/钱包/电脑；群聊协作；线下扫码触点。
- **体验**：身份即产品；外联叙事强；预算控支付。
- **适合学**：agent 社会化身份、生活服务闭环。

### 腾讯 WorkBuddy
- **产品**：职场桌面 Agent；本地文件；专家/技能；IM 遥控器；可验收交付物。
- **体验**：Ask/Plan/Craft；任务-结果双栏；中文办公场景深。
- **适合学**：模式化风险控制、交付物导向 UI、本土协作入口。

### Today AI
- **产品**：已活记忆的全天个人助理；跨 Mac/iOS/Android；云电脑 + Connectors；国内接飞书/钉钉/微信/腾讯文档；目前免费。
- **体验**：单窗口连续对话；Living Memory 可检视编辑；早晚简报主动介入；外发必确认；微信好友化使用。
- **适合学**：记忆可信交互、克制型主动性、国内生态里的 Personal 连续性；警惕任务轻重判断失效。

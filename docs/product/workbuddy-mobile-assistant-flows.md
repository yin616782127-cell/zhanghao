# WorkBuddy 移动端个人助理：两套方案方向与对话流程

> 用途：补齐产品流程稿。含产品方向、信息架构、旁聊/任务判定、真实对话脚本、端到端流程。
> 人物：用户「你」；助理「Max」。场景默认工作日早晨打开 App。

---

## 总对比（补流程图时可用）

| 维度 | 方案一：任务与助理并存 | 方案二：主对话 + 旁聊 |
| --- | --- | --- |
| 心智模型 | 「任务是主场，Max 是置顶对话」 | 「Max 是主场，旁聊是任务工作区」 |
| 入口 | 侧边栏置顶「和 Max 的对话」 | Home 默认主对话（问候 + 建议 + 输入） |
| 工作产物放哪 | 普通任务线程（可从 Max 跳转/新建） | 旁聊（由 Max 判定创建，或用户主动开） |
| 与现有任务体系 | 强兼容：助理只是特殊任务 | 需新增「主对话 / 旁聊」关系 |
| 类比 | ChatGPT Projects 列表里固定有一个 Assistant | Claude 主会话 + 旁支；Muse 主画布 + 专题 |
| 风险 | Max 容易被埋在列表里；跨任务记忆弱 | 任务列表心智被弱化；旁聊过多易乱 |

**选型建议（产品侧）**

- 若短期必须贴合现有「任务 / 分组 / 定时任务」导航，且改动面要小 → **优先方案一**。
- 若目标是对标 Claude Duet / Muse，把「助理」做成默认工作方式，任务从对话中生长 → **优先方案二**。
- 也可分阶段：先上方案一验证「置顶 Max」使用率，再演进到方案二的主/旁聊关系。

---

## 方案一：任务与助理并存

### 1. 产品方向

- **组织单位仍是任务**：侧边栏 = 置顶 / 最近 / 分组；「+ 新建任务」仍是主 CTA。
- **Max 是特殊任务**：系统预置、不可删除（可归档/静音）、固定置顶，标题「和 Max 的对话」。
- **职责边界**
  - Max 对话：跨任务咨询、计划、分流、轻量问答、帮助用户决定「开哪个任务」。
  - 普通任务：有明确交付物或长上下文的工作（PPT、周报、STM32、酸奶配方等）。
- **分流原则**：闲聊 / 元问题留在 Max；一旦出现可命名的交付物或需独立上下文的工作，引导用户进入已有任务或「+ 新建任务」。

### 2. 信息架构（对应稿图侧边栏）

```
Home Sidebar
├─ Header：全部任务 ▾ | 搜索 | 通知
├─ CTA：+ 新建任务
├─ 置顶
│  └─ 和 Max 的对话          ← 个人助理（特殊任务）
├─ 最近
│  ├─ 设计报告PPT大纲 ●
│  ├─ 怎么提升专注力
│  ├─ STM 32开发
│  └─ …
└─ 分组
   ├─ 每日 AI 行业资讯扫描
   ├─ 每日工作周报
   └─ 设计系统
```

### 3. 关键流程节点（可直接贴进流程稿）

1. 打开 App → 默认落在「最近最后一个任务」或「上次离开的任务」（产品可配；**不默认进 Max**，避免抢任务心智）。
2. 用户点汉堡/侧栏 → 看到置顶「和 Max 的对话」。
3. 进入 Max → 短问候 + 可选「继续上次建议」或「帮我看看今天任务」。
4. 用户提需求 → Max 判定：
   - **留在本对话**：建议、对比、追问、轻量一步答完。
   - **跳转已有任务**：匹配最近/分组里的任务，出卡片「去 XXX 继续」。
   - **建议新建任务**：出卡片「创建任务：YYY」→ 确认后新建并跳转，Max 侧留一句摘要链接。
5. 在普通任务内：可「@Max」或顶部「问 Max」拉起助理浮层（可选二期）；一期可只靠侧栏切回 Max。

### 4. Max 分流判定（方案一）

| 用户意图信号 | 动作 |
| --- | --- |
| 闲聊、今日计划、怎么用 App、泛问「帮我想想」 | 留在 Max |
| 明确提到已有任务名/主题（如「PPT 大纲」） | 推荐打开对应任务 |
| 出现交付物词：报告/PPT/代码/周报/调研 + 需要多轮 | 建议新建任务 |
| 定时/重复（每天扫描资讯） | 引导分组或定时任务，不塞在 Max 长聊 |

### 5. 真实对话脚本 A：留在 Max（今日计划）

**入口**：侧栏 → 和 Max 的对话

```
Max：早。昨天你还在改「设计报告PPT大纲」，今天想先推进哪件？

你：帮我排一下今天，我大概只有 3 小时能深度工作。

Max：按截止和卡点，我建议：
1. 09:30–11:00  设计报告PPT大纲（卡在「竞品页」）
2. 11:00–11:30  每日工作周报 · 先列 3 条要点
3. 下午碎片时间再看「怎么提升专注力」那篇笔记

要我直接打开「设计报告PPT大纲」吗？

你：好。

Max：[卡片] 打开任务 · 设计报告PPT大纲
     我会把刚才的时间盒记在任务备注里。
```

**流程要点**：问候 → 结合最近任务给计划 → 一键跳转任务（不在 Max 里写完 PPT）。

### 6. 真实对话脚本 B：建议新建任务（新课题）

**入口**：Max 对话

```
你：我想做一个 STM32 的呼吸灯 Demo，从零到能烧录，分步骤教我。

Max：这会是一个持续多天的小项目，建议单独开任务，方便留代码、引脚图和踩坑记录。
     任务名可用：「STM32 呼吸灯 Demo」
     [按钮] 创建并开始  [按钮] 先在这里快速讲一轮

你：创建并开始。

系统：新建任务「STM32 呼吸灯 Demo」→ 跳转该任务线程

Max（任务内首条系统代发或迁移摘要）：
目标：呼吸灯 Demo，从零到烧录。
建议第一步：确认板型号与开发环境（Keil / CubeIDE / PlatformIO）。
你现在用的是哪块板？
```

**流程要点**：识别「多日项目」→ 提案建任务 → 用户确认 → 上下文迁移到任务 → Max 对话留一条「已创建」回执。

### 7. 真实对话脚本 C：匹配已有任务（带红点）

```
你：PPT 竞品那页怎么写比较好？

Max：你指的是「设计报告PPT大纲」里还没写完的竞品页吧？那边有未读更新。
     [卡片] 去任务继续 · 设计报告PPT大纲 ●
     跳过去后我可以直接按你现有大纲改一版竞品页结构。
```

### 8. 方案一边界案例

| 案例 | 期望行为 |
| --- | --- |
| 用户坚持在 Max 里写完整 PPT | 允许，但第 3 轮后轻提示「内容变长了，挪到任务更清晰」；不强制 |
| 用户删除/长按 Max | 不可删除；可「清空对话」或「暂时从置顶拿下」（产品二选一，建议仅清空） |
| 从分组定时任务进来 | 任务内完成；需要跨任务建议时再回 Max |

## 方案二：主对话 + 旁聊（类 Claude Duet / Muse）

### 1. 产品方向

- **Home = Max 主对话**：问候、能力建议（数据分析 / 文档 / 幻灯片 / 深度研究）、语音输入；底栏仍保留任务等入口。
- **主对话职责**：默认助理；理解意图、澄清、编排；**判定是否建旁聊**。
- **旁聊 = 专题工作区**：有独立标题、文件/产物、可被底栏「任务」列表聚合展示；类似「从主对话长出来的任务线程」。
- **关系**：主对话 1 : N 旁聊；旁聊可回链主对话摘要；主对话不承载长交付物正文。

### 2. 信息架构（对应稿图 Home）

```
Home（主对话）
├─ Header：菜单 | WorkBuddy | 云电脑状态
├─ 空态：Max 形象 +「Max，我帮你」+ 建议 Chip
├─ 有对话时：主对话消息流
├─ 输入：语音 | 发消息或按住说话 | +
└─ 底栏：任务 | 定时任务 | 发现 | 我的

旁聊（从主对话拉起）
├─ 标题：如「Q3 设计报告 PPT」
├─ 独立消息流 + 产物区
└─ 可返回主对话 / 在任务列表中出现
```

### 3. 关键流程节点

1. 打开 App → **默认进入主对话空态**（Max + 建议 Chip）。
2. 用户点 Chip 或输入自然语言。
3. Max 在主对话澄清（目标、材料、截止时间）——通常 1～3 轮。
4. **建旁聊判定**（见下节）通过后：
   - Max 提案：「这块适合开一个旁聊专注做，标题建议 …」
   - 用户确认 / 或高置信度自动创建并提示「已为你开旁聊」。
5. 进入旁聊完成交付；关键结论回流主对话一条摘要。
6. 底栏「任务」：旁聊与传统任务统一列表（旁聊带来源标记「来自 Max」）。

### 4. 建旁聊判定规则（方案二核心）

**建议建旁聊（满足 ≥2 条，或 1 条强信号）**

| 信号类型 | 例子 |
| --- | --- |
| 强：明确交付物 | 「做一份幻灯片」「出周报」「写分析报告」 |
| 强：需要上传/多文件 | 「根据这两个 Excel」「这份 PDF」 |
| 强：预计 >3 轮专深 | 「从零做 STM32 Demo」 |
| 弱：要保存可回看上下文 | 「后面几天还要改」 |
| 弱：要和别的主题隔离 | 「先别跟周报混在一起」 |

**不建旁聊（留在主对话）**

- 单次问答、概念解释、今日安排、选 Chip 后的一句话演示。
- 纯路由：「帮我打开昨天的旁聊」。
- 用户明确说：「就在这里说就行」。

**冲突处理**

- 用户正在旁聊 A，主对话又提新交付物 → 新旁聊 B，不污染 A。
- 与已有旁聊主题重合 → 先推荐「回到旁聊：XXX」，而非新建。

### 5. 真实对话脚本 D：主对话澄清 → 建旁聊（做 PPT）

**入口**：Home 主对话，用户点 Chip「做一份幻灯片」或输入

```
你：做一份幻灯片

Max：好。先定三件事，我再开旁聊专心做稿：
1. 主题/场合？（例：设计周会汇报）
2. 页数大概多少？
3. 有没有现成大纲或素材？

你：设计周会，大概 10 页，大纲在「设计报告」那个旧任务里有一版。

Max：明白。我会新建旁聊「设计周会 PPT · 10页」，并把你提到的大纲当作起点。
     之后改稿、导出都在旁聊里，主对话只留进度摘要。
     [按钮] 创建旁聊并开始  [按钮] 先在主对话出个目录

你：创建旁聊并开始。

系统：创建旁聊 → 进入「设计周会 PPT · 10页」

Max（旁聊内）：
先给你一版 10 页目录，你改标题即可，我再往下填内容：
1. 封面
2. 本周目标
3. 进展总览
…
要先改目录，还是直接按这个填？
```

**主对话回流（旁聊产生首版后）**

```
Max（主对话系统摘要）：
旁聊「设计周会 PPT · 10页」已生成目录初稿。
[卡片] 回到旁聊
```

### 6. 真实对话脚本 E：主对话内完成（不建旁聊）

```
你：怎么提升专注力，给我 3 个今天就能用的方法。

Max：今天就能用的三个：
1. 90 分钟只留一个窗口，手机进另一个房间
2. 开始前写下「这一段只做的一件事」
3. 每段结束只休息 5 分钟，不刷信息流

需要我按你下午的会议时间，帮你排两个专注块吗？
（仍在主对话；若用户说「排进日程并天天提醒」→ 再引导定时任务/旁聊）
```

### 7. 真实对话脚本 F：高置信度自动建旁聊 + 可撤销

```
你：把这份销售 CSV 做转化漏斗分析和三张图，今晚要用。
（已附文件 sales.csv）

Max：收到 sales.csv。这是典型的「数据分析和可视化」交付，我直接开了旁聊：
     「销售转化漏斗 · 今日」
     [卡片] 进入旁聊    [链接] 撤销并留在主对话

（若用户点撤销：旁聊归档/删除，后续回答回到主对话）
```

### 8. 真实对话脚本 G：匹配已有旁聊

```
你：PPT 竞品页还是不满意。

Max：你有一个进行中的旁聊「设计周会 PPT · 10页」，竞品页在第 4 页。
     [卡片] 回到旁聊继续改
     还是要新开一版完全不同的结构？
```

### 9. 方案二与底栏「任务」的关系（补流程必写）

- **任务 Tab**：列表 = 旁聊 ∪ 用户手建任务 ∪ 定时任务实例（展示层可分组）。
- **主对话不算任务**：不出现在任务列表；或置顶显示「Max 主对话」入口（推荐后者，降低迷路）。
- **定时任务**：到点触发时，优先推入对应旁聊/任务；无则主对话提醒 + 建议建旁聊。

### 10. 方案二边界案例

| 案例 | 期望行为 |
| --- | --- |
| Chip「换一换」 | 只换建议，不产生旁聊 |
| 用户在主对话上传大文件但说「随便看看」 | 先主对话速览；若开始要图表/报告再提案旁聊 |
| 旁聊过多 | 主对话主动建议归档；任务列表按最近/置顶 |

## 共用：建议写入 PRD 的状态与埋点

### 状态

- 方案一任务类型：`assistant_root` | `normal_task`
- 方案二会话类型：`main` | `side`；旁聊字段：`parent_main_id`、`spawn_reason`、`linked_task_id?`

### 关键埋点（便于两方案 A/B）

- `assistant_entry`（sidebar_pin / home_main）
- `handoff_to_task` / `spawn_side_chat`（含 reason、user_confirm | auto）
- `spawn_rejected` / `spawn_undone`
- `return_to_main_from_side`

## 附录：一句话电梯稿（对内对齐用）

- **方案一**：Max 是侧栏里永远置顶的那个对话；活仍在任务里干，Max 负责想清楚和带你过去。
- **方案二**：打开就是 Max；活一旦够「专题」，Max 给你开旁聊，主对话只保留导航和摘要。
